# アプリ内更新の運用

macOS / Apple Silicon の安定版を GitHub Release から配布する。
アプリは起動15秒後、その後は最終試行から24時間以上経過していれば確認する。
自動確認は既定でオン、自動更新は既定でオフ。手動確認は Help メニューと設定にある。
自動更新をオンにすると自動確認も有効になる。自動確認をオフにすると自動更新もオフになる。

## 更新の適用

「終了時に更新する」、または自動更新でアーカイブをダウンロードすると、
署名検証済みのデータをメモリに保持する。作業中にインストールや再起動はしない。
通常終了時にアプリの終了を保留し、各ウィンドウの操作を止めて未保存編集を保存する。
構造変更のキューと重なっている保存をすべて待ち、実際の保存結果を確認する。
本文が未編集でも、失敗した構造変更があれば保存成功と応答しない。
本文の保存失敗は、新しい本文を含む保存が成功すれば解消する。
失敗した構造変更は、その変更内容を再試行して保存できれば解消する。
保存処理の完了順が逆転しても、新しい本文の失敗を古い保存成功で解消しない。
全ウィンドウが保存成功を応答したら、バックグラウンドで更新を適用して終了する。
次回起動から新しい版になる。保存失敗・応答タイムアウト・新しいウィンドウが開いた場合は
終了を取り消し、編集を続けられる。適用失敗もアプリ内に表示し、再ダウンロードできる。
macOS の管理者認証が必要な場合もイベントループを維持する。

ダウンロード中に自動更新をオフにすると、ダウンロード済みデータを自動適用しない。
ユーザーが明示的に「終了時に更新する」を選んだものは適用する。
クラッシュや強制終了では更新されず、次の確認時にダウンロードし直す。

## 配布の初期設定

Apple Developer ID の署名・公証とは別に、Tauri updater 用の署名鍵を用意する。
[Tauri 公式手順](https://v2.tauri.app/plugin/updater/)に従って
`bunx tauri signer generate -w <安全な保存先>/updater.key` を実行する。
秘密鍵とパスワードを安全な場所にバックアップし、秘密鍵をリポジトリに含めない。
既存の鍵がある場合はそれを使う。

GitHub リポジトリに次を設定する。

- Variable `TAURI_UPDATER_PUBLIC_KEY`: 生成された `.pub` ファイルの内容
- Secret `TAURI_SIGNING_PRIVATE_KEY`: 秘密鍵ファイルの内容
- Secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: 鍵のパスワード（設定した場合）

公開鍵はリリースビルド時に Tauri 設定へ埋め込まれる。
通常の開発ビルドは公開鍵が空なのでネットワーク確認をせず、設定に「未設定」と表示する。
CI は鍵が未設定なら配布を失敗させる。
署名鍵を変更すると既存アプリは新しい署名を検証できないので、鍵の切り替えは別途移行が必要。

CI は署名・公証済み DMG に加えて updater 用の `.app.tar.gz` と `.sig` を公開する。
updater アーカイブは `Peitho-Studio_<version>_aarch64.app.tar.gz` という空白なしの名前で
アップロードする（GitHub はスペースを含む asset 名をドットに書き換えるため、
ローカルのファイル名から組み立てた URL は 404 になる）。
安定版では `latest.json` を生成し、そのファイル自体も `tauri signer sign` で署名し、
`latest.json` と `latest.json.sig` を成果物のアップロード後に公開する。
tagpr は GitHub Release を draft で作り（`.tagpr` の `release = draft`）、CI がすべての成果物を
アップロードしてから公開する。公開前は `releases/latest` が前の版を指し続けるので、
ビルド中に更新確認したアプリが manifest の 404 を受け取ることはない。
RC の成果物は生成するが、安定版更新 manifest は公開しない。
初回の更新対応版は、既存の更新機能がないアプリから手動でインストールする必要がある。
公開前に2つの署名・公証済みアプリ間で実機の更新検証を行う。

## セキュリティ告知

`meta/update-security.json` に告知を追加して修正版をリリースする。
すでに公開済みの告知は、対象範囲のユーザーに届き続けるよう残す。

```json
[
  {
    "affectedFrom": "0.1.0-rc.1",
    "fixedIn": "0.1.1",
    "reason": "プレビューにセキュリティ上の問題があります。更新してください。"
  }
]
```

`affectedFrom` 以上、`fixedIn` 未満に通知する。複数の告知を指定できる。
修正版は公開する安定版以下でなければならない。
告知と更新 URL・バージョンは署名付き manifest で保護し、
取得した署名付きデータと updater が使う manifest が一致することも確認する。
以前に確認した版より古い manifest は拒否する。新規端末への古い署名付き情報の
再配信まで完全に防ぐ仕組みではない（オンラインの鮮度保証サーバーは設けない）。

対象版では自動更新オフでも目立つ通知を出し、通常版の「後で」で非表示にできない。
セキュリティを理由に利用制限・強制終了・強制再起動は行わない。
一度確認した署名付き告知は保存し、次回オフライン起動でも表示できる。
オフラインまたは自動確認オフでは新しい告知を検出できないが、編集・保存は継続できる。

不具合版は配布を止め、修正版をより新しいバージョンで出す。
自動ダウングレードは行わない。手動インストールは設定の Releases から案内する。
