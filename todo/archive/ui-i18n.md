# UI表示言語の切り替え(日本語 / English)

進捗管理用の作業台帳 — **完了したら削除ないし`todo/archive/`へ移動する**。

発端: ユーザー要望「言語設定したい」。`todo/studio-settings-panel.md`
から切り出した。対象はStudio UI自体の表示言語で、peitho-coreの
`DeckLang`(デッキのコンテンツ言語)とは無関係。対応言語は日本語と
英語の2つ(2026-09-24にユーザー確認済み)。

**着手条件**: `todo/studio-settings-panel.md`が完了していること(設定の
保存の仕組みと設定画面ができていること)。

## スコープ

- **目的**: 設定画面で表示言語(日本語 / English)を選ぶと、Studioの画面の
  文言がその言語で表示される。
- **やらないこと**:
  - 日本語と英語以外の言語
  - デッキの内容やpeitho-coreのエラーメッセージの翻訳(エンジンが返す
    文言はそのまま表示する)
  - `DeckLang`の設定UI
- **受け入れ条件**:
  - 設定画面で言語を切り替えると、再起動なしで、開いている全ウィンドウの
    画面の文言が切り替わる。再起動後も保持される。
  - 初回起動時(設定がまだないとき)は、OSの優先言語が日本語なら日本語、
    それ以外なら英語で表示する。
  - ネイティブのメニューバー(File/Edit/Window/Help など、
    `src-tauri/src/lib.rs`で組み立てているもの)も同じ言語で表示される。

## 背景・要調査

実際に読んで分かったこと:

- BarefootJSにはi18nの仕組みがない(`@barefootjs/client`にあるのは日付の
  書式関数`formatDate`だけ)。訳語の表と「現在の言語」のsignalを自前で
  持つ。
- 画面の文言は各`components/*.tsx`に英語で直接書かれている。
- ネイティブのメニューは`build_menu_with_recents`がメニュー全体を毎回
  作り直す作りなので、言語が変わったときも作り直せばよい。
  `PredefinedMenuItem`(Cut/Copy/Paste など)の表示はOSの言語に従う
  ことがあるので、実機でどう見えるかを確かめる。

要調査:

- 訳語の表の置き場所と、コンポーネントからの呼び方。CLAUDE.mdの
  BarefootJSの落とし穴(propsには値を渡す、`const`のローカル変数は
  JSXの属性で固まる、`Map`全体を1つのsignalに持たない)に当たらない
  書き方を、`barefootjs` skillで確かめてから決める。
- 状態メッセージ(`setStatusMessage('Saved')`など)のように、
  コンポーネント以外で作られる文言の扱い。

## 方針

- 訳語の表は`domain/`に純粋に置く(例: `domain/messages.ts`)。
  キーは型で表し、日本語と英語の両方に同じキーがそろっていることを
  型チェックで保証する。
- 現在の言語は設定のstoreから読む。

## レイヤー配置

- `domain/messages.ts`(新規、純粋): 訳語の表と、言語とキーから文言を
  返す関数。OSの優先言語から初期言語を決める関数。
- `state/`: 設定のstoreの言語を参照する。
- `components/*.tsx`: 直書きの文言を置き換える。
- `src-tauri/src/lib.rs`: メニューの文言を言語に応じて切り替える。
  訳語はRust側にも持つ。

## テスト

- `domain/messages.ts`: spec(両言語で文言が返る)とadversarial(未知の
  言語、OSの言語が空文字や想定外の形式)。両言語のキーがそろっている
  ことのテスト。
- e2e: 言語を切り替えると、代表的な文言(ウェルカム画面、右クリック
  メニュー)が切り替わること。
- Rust: 言語ごとのメニューの文言を返す関数を切り出して`#[cfg(test)]`。

## 実装メモ

- 設定の`uiLanguage`は`system`/`en`/`ja`。`system`(既定)はOSの
  優先言語に従う。設定画面の選択肢は日本語/Englishの2つで、選ぶと
  明示的な値として保存される(`system`へ戻す操作は用意していない)。
- 状態メッセージ(`domain/statusMessage.ts`)とレイアウトの通知
  (`LayoutNotice`)は文言ではなく「何が起きたか」を持ち、表示時に
  訳すので、言語を切り替えると表示中のものも切り替わる。
- 新規スライドの見出し(`# New Slide`)や新規セクション名
  (`New Section`)はデッキの内容に書き込まれるので訳さない。

実機確認の結果(2026-09-25、ユーザー): 日本語の訳語、言語の切り替え、メニューバーの表示、再起動後の保持は、いずれも問題なし。
