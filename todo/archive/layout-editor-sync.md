# レイアウトエディタの自動保存と外部変更の自動反映

進捗管理用の作業台帳 — **完了したら削除ないし`todo/archive/`へ移動する**。

発端: ユーザーの要望(2026-10-04、PR #163の実機確認中)。「エディタで編集したら、
自動保存が良さそう。また、コメント経由で、AIに編集してもらったら、エディタ側にも
自動反映されると良さそう。相互に編集できると良いな」。

前提: `todo/layout-screen.md`(#157、レイアウト画面と明示保存)、
`todo/layout-review-comments.md`(#162、コメント→crit→エージェント)、
`todo/layout-screen-rearrange.md`(#163、配置の組み替え)。

## スコープ

- **目的**: レイアウトのHTML/CSSを、スライドの本文と同じく「書けば保存される」
  ものにし、エージェントがファイルを書き換えたら開いているエディタにそのまま
  反映されるようにする。Studioとエージェントが同じレイアウトを交互に編集できる。
- **やらないこと**:
  - 同時編集のマージ(3-way merge・OT)。衝突時は方針の規則で片方を取る。
  - `deck.md`側の外部変更の扱いの変更(既存の`handleExternalChange`のまま)。
  - 下書きフォントの分離(issue #161)。
  - frontmatterの`layouts:`/`css:`パス指定への対応。
- **受け入れ条件**:
  - レイアウトのHTML/CSSを編集して手を止めると、一定時間(方針で決める)後に
    保存される。「保存」ボタンは不要になる(残すかは方針)。
  - 保存前検査(`save_layout`の「ビルドできるか」)に通らない下書きは保存されず、
    エラーが出て、下書きはエディタに残る。直せば次の自動保存で保存される。
  - 別のレイアウトへの切替・画面の切替・ウィンドウを閉じる時に、保存待ちの
    下書きを先に保存する(保存できなければ切替を止めて知らせる — 既存の
    「保存か元に戻すを先に」と同じ扱い)。
  - エージェント(や外部エディタ)が`layouts/*.html`/`css/*.css`を書き換えると、
    critの通知を待たずに検知され、一覧・サムネイル・スライドが描き直され、
    開いているレイアウトならエディタの中身も更新される。
  - エディタに未保存の下書きがある時に同じファイルが外部で変わった場合、
    方針の規則どおりに扱われ、黙ってどちらかが消えることはない。
  - Studio自身の自動保存が、外部変更として二重に反映されない。

## 背景・要調査

読んで分かったこと:

- 今のレイアウトエディタは明示保存(「保存」/「元に戻す」、`saveShownLayout`)。
  保存前に`flushDeck()`で`deck.md`を保存し、`save_layout`がビルド可否を検査して
  から書く(#157)。下書きのライブプレビューは入力停止後250ms
  (`DRAFT_PREVIEW_DELAY_MS`)。
- スライド本文は入力のたびに描画と保存が走る(`state/saveTracker.ts`の
  draft/structural)。
- ファイル監視は`deck.md`だけ(`src-tauri/src/peitho.rs`の`watch_deck_file`:
  `notify`のwatcher、250msの静穏待ち、`DECK_FILE_CHANGED_EVENT`をそのウィンドウ
  にだけ送る)。`deck.md`の外部変更は`Studio.tsx`の`handleExternalChange`で扱う。
- レイアウトファイルの外部変更は、critのイベント(`critIpc.onReviewEvent`)の
  たびに`syncLayoutFiles()`が`layout_files_stamp`を読み、変わっていれば
  `refreshLayouts(null)`する(#162)。critを通さない変更(外部エディタ、critの
  イベント前のエージェントの書き込み)は拾えない。
- CLAUDE.mdの落とし穴: ウィンドウごとの状態は`window.label()`をキーにした
  マップで持つ(監視もウィンドウごと)。

要調査:
1. `handleExternalChange`が`deck.md`の外部変更と未保存の下書きの衝突をどう
   扱っているか。レイアウト側も同じ規則に揃える。
2. 自動保存の書き込みが監視に拾われた時に、自分の書き込みと見分ける方法
   (書いた内容/指紋を覚えておき、一致すれば無視する、など)。

### 調査結果

1. **`deck.md`の衝突の扱い**: `handleExternalChange`は、未保存の下書きが
   無ければそのまま読み直す。下書きがあると`window.confirm`で「読み直して
   破棄するか」を尋ね、断れば開いているスライドだけ下書きを残して残りを
   ディスクの内容に揃える。どちらにしても黙って消すことはしないが、
   `window.confirm`はWKWebViewで当てにならない(CLAUDE.md)。レイアウト側は
   同じ「黙って消さない」規則を、アプリ内のお知らせ(「ディスクの内容を
   読み込む / 自分の編集を残す」)で実現した。`deck.md`側は変えていない
   (スコープ外)。
2. **自分の書き込みの見分け方**: 二重にしている。(a) `save_layout`が書いた
   直後の指紋(`layout_files_stamp`)を返し、フロントはそれを「見た指紋」と
   して覚える。監視の報告(250msの静穏待ちの後)で読む指紋が同じなら何も
   しない。(b) それでも読み直した場合も、開いているレイアウトの内容が
   エディタの`saved`と同じなら`unchanged`で何も変えない
   (`withExternalChange`)。

### 実装メモ

- 「保存」「元に戻す」ボタンは外した。入力停止1000ms(`LAYOUT_AUTOSAVE_DELAY_MS`)
  で保存し、保存は1本ずつ直列。保存中の状態は「保存中…」、未保存は●で示す。
- 検査で拒否された下書きは次の編集まで再試行しない(拒否のたびに検査を
  繰り返さない)。
- レイアウトの切替・画面の切替・新規作成/複製の前に保存待ちを先に保存する。
  保存できない(拒否・衝突中)なら切替を止めてお知らせを出す。
- ウィンドウを閉じる時: フロントが「未保存の下書きがあるか」を
  `report_layout_draft`で知らせておき、Rust側の`CloseRequested`で
  下書きがあれば閉じるのを止めて`layout:flush-before-close`を送る。
  保存できればフロントがもう一度閉じる。保存できなければお知らせを出し、
  もう一度閉じれば下書きを捨てて閉じる(フロントが応答しなくても
  ウィンドウが閉じられなくならないように、2回目の閉じる操作は必ず通す)。
- 外部変更は`layouts/`・`css/`(とデッキのフォルダ自体、後からフォルダが
  できた時のため)を非再帰で監視する。エディタへの反映はCodeMirrorの
  1トランザクションで、Cmd+Zで取り消せる(取り消した内容は普通の編集として
  自動保存される)。

## 方針

- **自動保存**: 入力停止後に保存する。間隔はライブプレビュー(250ms)より長め
  (推奨: 1000ms前後)にして、検査付きの保存が入力中に何度も走らないようにする。
  保存は直列化し、古い保存の結果が新しい下書きを上書きしないようにする
  (`layoutDraftPreview`と同じ番号付けの考え方)。
- **「保存」「元に戻す」ボタン**: 「保存」は外す。「元に戻す」は「最後に保存した
  内容に戻す」意味が薄れるので、エディタのUndo(Cmd+Z)に任せて外す方向
  (実装時に判断、人間確認項目)。
- **外部変更の検知**: `layouts/`と`css/`をウィンドウごとに監視する
  (`watch_deck_file`と同じ形、ディレクトリを非再帰で)。変更が来たら
  `syncLayoutFiles()`と同じ経路で描き直す。critイベント経由の`syncLayoutFiles`は
  残してよい(重複しても指紋で1回に収まる)。
- **エディタへの反映**:
  - 開いているレイアウトのファイルが変わり、エディタに未保存の下書きが
    無ければ、エディタの中身を新しい内容に差し替える。CodeMirrorの1つの
    トランザクションとして入れ、Cmd+Zでエージェントの変更を取り消せるように
    する。カーソル位置はできるだけ保つ。
  - 未保存の下書きがある時(自動保存待ちの数百ms〜、または検査に通らず保存
    できていない下書き): 黙って捨てない。推奨は「ディスクの方が新しくなりました
    — 読み込む / 自分の編集を残す」のお知らせを出し、選ばせる(アプリ内UI。
    `window.confirm`は使わない)。要調査1の結果、`deck.md`と同じ規則があれば
    それに揃える。
- **自分の書き込みの除外**: 自動保存で書いた内容の指紋を覚え、監視から来た
  変更の指紋と同じなら何もしない。

## レイヤー配置

- Rust `engine/`: 監視対象パスの決定、指紋の計算など純粋な部分。
- Rust `peitho.rs`: レイアウト用watcherの保持(ウィンドウごと、
  `PeithoSession`に)とイベント送出。`lib.rs`は登録のみ。
- フロント `domain/`: 自動保存のスケジュール/直列化の状態、外部変更と下書きの
  衝突の判定(ADT)。
- `state/layoutScreenStore.ts`: 上記の状態。`ipc/deckIpc.ts`+`fakeDeckIpc`:
  新イベント。`components/LayoutScreen.tsx`: ボタンの整理、衝突のお知らせ。
  配線は`Studio.tsx`。
