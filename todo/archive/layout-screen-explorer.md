# レイアウト画面の再設計: ファイル | エディタ | レイアウト一覧

進捗管理用の作業台帳 — **完了したら削除ないし`todo/archive/`へ移動する**。

発端: ユーザーとの相談(2026-10-05)。HTMLモック
(https://claude.ai/artifact/HApLhaYFqAwQjszxr3wFft の「提案B」)で方向性を確認した。
- 左にVS CodeのExplorerのようなファイルツリーを置き、`base.css`など共有ファイルも
  Studioの中で編集できるようにする。
- 中央はエディタ。開いたファイルをタブで並べる。
- 右はレイアウト一覧。プレビューを兼ねる(選択中のレイアウトを上に大きく、
  他は2列の小さなサムネイル)。`base.css`を編集すると全サムネイルに効き、
  影響範囲が一目で分かる。
- スライド画面とは「左=選ぶ場所、右=見た目の結果」の規則で揃える。
追加の要望: 一覧にレイアウトの英名(ファイル名)も表示する。エディタでも
コメントしてAI Agentに依頼できるようにする。
「JavaScriptのタブ」は今回は扱わない(ユーザー指示)。

前提: `todo/archive/layout-screen-rearrange.md`(#163: エディタ|一覧、選択行のライブ描画、
サムネイルのクリックでコメント)、`todo/archive/layout-editor-sync.md`(#164: 自動保存、

## スコープ

- **目的**: レイアウト画面を、ファイル単位で自由に編集できる作業場にしつつ、
  レイアウト単位の操作(適用・複製・削除・コメント)と見た目の確認を右の一覧に
  集める。
- **やらないこと**:
  - JavaScriptのタブ、`layouts/<name>.js`のような別ファイルの規約。
  - ファイルツリーでの作成・リネーム・削除・移動(最初は「開く・編集する」だけ。
    レイアウトの作成・複製・削除は従来どおり一覧の右クリックで行う)。
  - 画像・フォントなどバイナリファイルの編集(ツリーには出すが、開いても
    編集できない。プレビュー表示もしない — 先送り)。
  - `deck.md`の編集(スライド画面で行う。ツリーには出さない)。
  - issue #161(下書きフォントの分離)。
- **受け入れ条件**:
  - レイアウト画面が左から「ファイルツリー | エディタ | レイアウト一覧 | コメント列」
    の順に並ぶ。境界はドラッグで幅を変えられる。
  - **ファイルツリー**: `layouts/`・`css/`・`img/`・`fonts/`を表示し、フォルダを
    開閉できる。テキストファイル(`.html`/`.css`)を選ぶとエディタのタブで開く。
  - **エディタ**: 開いたファイルをタブで並べ、切り替え・閉じることができる。
    どのファイルも自動保存され(#164と同じ間隔と保存前検査)、外部での変更が
    反映される(#164の衝突のお知らせも同じ)。`css/base.css`など、どのレイアウトの
    組にも属さないファイルも編集・保存できる。
  - **レイアウト一覧**:
    - 選択中のレイアウトは上に大きく表示し、編集中の内容をライブで描く(#163の
      下書き描画を移す)。他のレイアウトは下に2列の小さなサムネイル。
    - 各レイアウトに表示名と**英名(ファイル名、例: `title-body`)**の両方を出す。
    - 右クリックのメニュー: スライドに適用 / 複製 / このレイアウトにコメント… /
      削除…(空白の右クリック: 新規レイアウト / レイアウト全体にコメント…)。
      「レイアウトを編集」は無い。
    - PC/スマホ切替は一覧の左上(#165の端末プリセット・実寸表示はそのまま)。
    - 大きく表示した選択中のレイアウトをクリックすると、AIへのコメント欄が開く
      (#163のslot判定つき)。
  - **選択の連動**:
    - 一覧でレイアウトを選ぶと、その`.html`と`.css`がエディタのタブで開き、
      ツリーでも強調される。
    - ツリーでレイアウトの`.html`/`.css`を開くと、一覧でもそのレイアウトが選ばれる。
    - どのレイアウトにも属さないファイル(`base.css`など)を開いた時は、一覧の
      選択はそのまま(最後に選んだレイアウトを大きく表示し続ける)。
  - **エディタからのコメント**: エディタで行を選んで(またはカーソル行で)コメント
    すると、そのファイルのその行範囲へのコメントとしてcrit経由でエージェントに
    届く。ラベルは`[layouts/title-body.html L3-L5 "…引用…"]`のようにファイル名・
    行・引用を含む。スライド画面と同じコメント欄(`CommentBox`)と送信の流れを使う。
    開始は右クリックメニュー(下の「右クリックでコメント」)。

## 背景・要調査

読んで分かったこと:

- 今の配置(#163): エディタ | 一覧(選択行の下書きライブ描画、サムネイルクリックで
  コメント) | コメント列。エディタはHTML/CSSの2タブで、1つのレイアウトの組
  (`layouts/<name>.html` + `css/<name>.css`)しか開けない。`base.css`は触れない。
- 保存は`save_layout`(レイアウトの組単位、保存前にビルド検査)。自動保存・外部変更の
  反映は#164(`layout_files_stamp`、`layouts/`・`css/`の監視、衝突のお知らせ)。
- レイアウトへのコメントは`NewLayoutComment { layout: string | null, body, author }`
  (`domain/critReview.ts`、`src-tauri/src/engine/crit.rs`の`layout_comment_place`)で、
  行の情報を持たない(ファイル全体、またはreview-level)。一方、`deck.md`への
  コメントは`start_line`/`end_line`/`quote`つきで送っている(`POST /api/file/comments`)。
  critのセッションは`deck.md layouts css`を対象にしているので、レイアウトの
  ファイルへの行コメントは同じAPIで送れるはず(要確認)。
- エディタは`dom/codeEditor.ts`(CodeMirror)。Vim mode、折り返しなし、Undoの扱いは
  #157/#163のまま。

要調査(実装の最初に確かめ、結果をここに書く):
1. critの`POST /api/file/comments?path=layouts/<name>.html`に`start_line`/`end_line`/
   `quote`を付けて送れるか(同梱critで実際に試す)。
2. `base.css`のようにレイアウトの組に属さないファイルを保存する時の検査:
   変更後に今ビルドできている全スライドがビルドできるかを検査する(`save_layout`の
   検査を一般化した`save_deck_text_file`のような形)。対象パスは`layouts/`・`css/`
   配下の`.html`/`.css`に限り、パスの検証(`..`やシンボリックリンク)を入れる。
3. ファイル一覧の取得: `layouts/`・`css/`・`img/`・`fonts/`を列挙するRustコマンド
   (サブディレクトリの扱い、隠しファイルの除外)。
4. CodeMirrorで選択範囲(行)を取得し、コメントの開始UIをどこに置くか:
   推奨は「選択中に出る小さな『コメント』ボタン」+エディタの右クリックメニュー。
   Vim modeのビジュアル選択でも使えること。

調査結果(実装時に確かめたこと):
1. critは`layouts/*.html`・`css/*.css`への行コメントを受け付ける。同梱critで
   `POST /api/file/comments?path=css/base.css`に`start_line`/`end_line`/`quote`を
   付けて送ると、一覧で行と引用つきで返り、エージェントにもファイルのパスつきで
   届く(`src-tauri/src/crit.rs`の
   `line_comments_on_layout_and_css_files_reach_the_agent_with_their_lines_and_quote`)。
   `NewLayoutComment`に`lines`(パス・行・引用)を足し、同じ
   `crit_add_layout_comments`で送る。
2. 保存は`save_deck_file`(`engine::deck_files`)。レイアウト自身のHTML/CSSは
   組のもう一方をディスク上のままにして`save_layout`の検査を通す(組の片方だけを
   書き、もう一方は書き直さない)。どのレイアウトにも属さないCSS(`base.css`)は
   変更後も今ビルドできているデッキがビルドできるかを検査する。対象は
   `layouts/<name>.html`・`css/<name>.css`(フォルダ直下、名前はレイアウト名と
   同じ文字種)に限り、`..`・絶対パス・サブフォルダ・シンボリックリンクは拒否。
   外部変更の監視は従来どおり(`css/*.css`は元から監視対象)。
3. `list_deck_files`は`layouts/`・`css/`・`img/`・`fonts/`を深さ8まで列挙する。
   隠しファイル・シンボリックリンクは出さない。フォルダを先、名前順。
4. 当初はエディタのツールバーの「コメント」ボタンにした(右クリックメニューは
   WKWebViewのネイティブメニューとの兼ね合いで見送り)。実機確認のあと、ユーザーと
   合意して右クリックメニューに置き換え、ボタンは削除した(下の「右クリックで
   コメント」)。

実装で決めたこと(計画と違う点):
- 一覧の2列グリッドには選択中のレイアウトも残す(サムネイルの枠で強調)。選ぶたびに
  グリッドの並びが動かないようにするため。大きな表示はグリッドの上。
- タブ化に伴い、別のレイアウトを選ぶ操作は保存できない編集があっても止めない
  (編集はそのタブに残る)。スライド画面への切替・新規レイアウト・ウィンドウを
  閉じる操作は従来どおり止め、問題のタブを前面に出す。
- 保存はファイル単位。HTMLとCSSを同時に変えないとビルドが通らない編集は、
  片方ずつ保存されるため途中で拒否されうる。

## 実機確認後の追加(2026-10-05)

ユーザーの実機確認を受けて、同じPRで次を加えた。

- **自己レビューの指摘3件**(いずれも残っていたので修正、回帰テストつき):
  - レイアウトのHTMLの自動保存が、組のCSSだけがディスク上で変わったために
    `LAYOUT_CHANGED_ON_DISK`で拒否されると、読み直してもHTMLは`unchanged`で、
    タブが未保存のまま止まっていた。読み直して保存すべき下書きが残っていれば
    自動保存をやり直す。

    そのままで、次の打鍵がエージェントの変更を上書きしていた。表示中のファイルは
    読み込んだ後に変換中かを見て、変換が終わるのを待ってやり直す。
  - 選択中のレイアウトの行をもう一度クリックしても、両方のタブを閉じた後だと
    開き直せなかった。閉じているファイルがあれば開き直す(`allTabsOpen`)。

  アイコンとして並び(コメント列のアイコンも同じレール)、押すと開く。中身は
  マウントしたまま。余った幅はエディタ→一覧→コメント列の順で埋める

  - スライドの本文・ノートのエディタ: 「この行にコメント…」(選択があれば
    「選択した行にコメント…」)、区切り、カット・コピー・ペースト。コメントは
    `deck.md`の行へ(`CommentTarget`の`lines`。要素へのコメントと同じく引用で
    探し直す)。ラベルは`[Slide 2 (key: intro) › lines L8-L10 "…"]`。

  - レイアウト画面のエディタ: 同じメニュー。コメントは開いているファイルの行へ

  - 決めたこと: エディタの右クリックは選択範囲の内側なら選択を保ち、外側なら
    そこへカーソルを移す(ネイティブのエディタと同じ。ペーストもそこに入る)。

## 実機確認後の追加2(2026-10-05、b848bc1の確認を受けて)

- **スライドのプレビューの右クリック = スライド一覧の行メニュー**: プレビューを
  右クリックすると、表示中のスライドに対してスライド一覧と同じ`SlideContextMenu`
  が開く(同じ項目・有効/無効の規則・処理。「レイアウトを変更 ▸」の選択肢も
  同じく画面内に収まる)。どこを右クリックしたかはメニューの状態
  (`ContextMenu`の`on-slide`の`comment`)が持ち、コメントは左クリックと同じ
  対象になる。一覧から開いたときはスライド全体。コメント専用だったプレビューの
  メニュー(`CommentMenu`の`on-slide-preview`)は廃止。
- **コメント項目の統一**: すべての右クリックメニュー(スライド一覧の行・
  スライドのプレビュー・本文/ノートのエディタ・レイアウトのエディタ・大きな
  プレビュー・レイアウト一覧の行・一覧の空白)で、先頭に同じ「コメント…」
  (EN: `Comment…`)を置き、その下に区切り線。吹き出しのアイコンを左に付ける。
  項目・ラベル・アイコン・区切りは`domain/menuComment.ts`の1か所で決める。

## レビュー指摘への対応(Pullfrog、b848bc1)

- エディタのメニューのカット・ペーストは、クリップボードの応答を待つ間に別の
  スライドやタブへ切り替わると、そちらの文書に古い位置で適用されていた。待つ前に
  対象(エディタ、スライドのキーまたはファイルのパス、文字)を控え、同じ対象が
  そのまま表示されているときだけ適用する。違えば取りやめる(カットはコピーだけ
  になる)。
- スライドの本文・ノートの行コメントで、フィールドの位置を保存後の文字列の検索で
  求めていたため、本文がキーと同じ文字(`intro`)だとPageCommentの行に付いていた。
  `buildSlideText`の書き方から位置を求める(`slideFieldStarts`)。
- 保存で落ちる空白(1行目の字下げ、最終行の末尾の空白)を引用に含めていたため、
  探し直せずスライド全体へのコメントになっていた。保存と同じ切り詰めを通して、
  残る部分を引用する。
