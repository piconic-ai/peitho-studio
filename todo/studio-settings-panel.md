# 設定画面の新設(UI表示言語 / アプリアイコン / vim mode調査)

進捗管理用の作業台帳 — **完了したら削除ないし`todo/archive/`へ移動する**。

発端はユーザー要望3件(「vim modeがほしい」「言語設定したい」
「アイコン設定したい」)。壁打ちで対象を確認済み:

- **言語設定** = Studio UI自体の表示言語切り替え(i18n)。peitho-coreの
  `DeckLang`(デッキのコンテンツ言語)とは無関係。
- **アイコン設定** = Peitho Studioアプリ自体(Dock/ウィンドウ)の
  アイコンをユーザーがカスタマイズできるようにする機能。デッキ/プレゼン
  ごとのアイコンではない。
- **vim mode** = 優先度低。現状`SlideEditor.tsx`は素の`<textarea>`
  (IME対策のため非制御コンポーネント — `Studio.tsx`の
  `syncEditorFields`参照)であり、vim modeの導入はこのtextarea実装を
  CodeMirror等の外部エディタライブラリへ丸ごと置き換える大改修が前提に
  なる。今回は実装せず、比較検討だけをこのファイルに残す。

どの要望も土台となる「設定を保存・表示するUI」自体がまだ存在しないため、
先に設定画面の基盤を作ってから各項目を載せる。

## スコープ

- **目的**: 設定の永続化基盤を作り、その上にUI表示言語切り替えと
  アプリアイコンのカスタマイズを実装する。vim modeは調査のみ。
- **やらないこと**: vim modeの実装そのもの(この段階では調査メモに
  留める。実装は調査結果を踏まえた別タスクとして切り出す)、
  日本語/English以外の言語への翻訳整備、peitho-coreの`DeckLang`
  (デッキのコンテンツ言語)設定UI。
- **受け入れ条件**: 設定画面が存在し、そこからUI表示言語(日本語/
  English)とアプリアイコンを変更でき、変更が再起動後も保持される。
  アプリアイコンについては、Tauri v2でランタイム変更が技術的に不可能と
  判明した場合、その旨をユーザーに報告し完了条件をその結果に合わせて
  修正する。

## 方針

### 設定の永続化

- Tauri v2の`tauri-plugin-store`(または単純に`AppHandle::path().
  app_config_dir()`配下へのJSON書き込み)のどちらを使うか、既存の
  `src-tauri/src/peitho.rs`の`PeithoSession`/`PendingDecks`と同じ
  「状態はMutexに集約、他モジュールに漏らさない」方針に沿う形で選定する。
  新規`src-tauri/src/settings.rs`のようなモジュールを切るのが筋が良さ
  そう(`peitho.rs`に混ぜない)。

### UI表示言語(i18n)

- BarefootJSでのi18n実現方法(文字列テーブル切り替えの標準的なやり方が
  あるか)を`barefootjs` skillで確認してから設計する。
- 対応言語は当面 日本語/English の2つで十分か、ユーザーに確認してから
  スコープを決める。

### アプリアイコン

- Tauri v2でランタイムにDock/ウィンドウアイコンを変更するAPIが存在する
  か要調査。存在しない場合、実行時カスタマイズは不可能で「ビルド時に
  アイコンを選べる」程度に後退する可能性がある — 調査結果次第では
  この要望自体の実現可否をユーザーに再確認する必要がある。

### vim mode(調査のみ、実装しない)

- CodeMirror 6 + vimキーバインド拡張が現実的な候補。導入する場合の
  影響範囲(`SlideEditor.tsx`の非制御textarea設計、IME対策コメントが
  指す挙動が今後も保たれるか)を書き出すだけに留め、実装はしない。
