# アプリのアップデート通知/自動更新

進捗管理用の作業台帳 — **完了したら削除ないし`todo/archive/`へ移動する**。

発端: ユーザーから、手動で確認して更新、自動更新の設定、新版の通知、
セキュリティ上必要な更新を強く促す仕組みが必要ではないかという提案。
セキュリティ更新は、自動更新がオフでも対象バージョンに強く通知する方針で合意。
完全オフラインで使えるアプリとして、更新までの利用制限は設けない。
実装済み: 手動確認、自動確認（既定オン）、自動更新（既定オフ）、通知、
署名付きセキュリティ告知、通常終了時の全ウィンドウ保存と更新適用。
運用手順は `docs/app-updates.md`。配布用の鍵設定と署名・公証済みアプリ間の
実機更新検証が残るため `wip` を維持する。

## 背景・要調査

- `package.json` / `src-tauri/Cargo.toml` に updater はなく、更新機能は未実装。
- 設定は `domain/settings.ts` と `src-tauri/src/settings.rs` で定義し、
  Rust 側に保存、全ウィンドウに変更を配信する既存の仕組みがある。
- 現在の配布対象は macOS / Apple Silicon。
  `.github/workflows/release-build.yml` は Developer ID 署名・公証済み DMG を
  GitHub Release に添付する。更新用成果物・署名・manifest の生成は未実装。
- [Tauri updater](https://v2.tauri.app/plugin/updater/) を採用する案。
  更新成果物には Apple 署名とは別の署名鍵と、アプリに埋め込む公開鍵が必要。
  `createUpdaterArtifacts`、更新 endpoint、CI での成果物と manifest の生成・公開を追加する。
  DMG 用の現行ビルド指定で更新成果物も生成できるか、実ビルドで確認する。
- 更新対応版が最初に配布されるまでは、既存ユーザーは手動で入れ替える必要がある。

## 方針案

更新を「確認 → ダウンロード・検証 → 適用 → 再起動」に分ける。
新版を見つけただけで編集中や発表中に再起動しない。

| きっかけ / 条件 | 動作案 |
| --- | --- |
| メニュー / 設定の「更新を確認」 | 頻度制限を待たず確認。新版ならバージョン・変更点・更新ボタンを表示。最新版ならその旨、失敗なら再試行を表示 |
| 自動確認 | 起動後に UI が落ち着いた時点、以後24時間ごと。復帰時も最終確認から24時間以上なら確認。複数ウィンドウで重複実行しない |
| 新版あり・自動更新オフ | アプリ内に更新案内。「更新」「後で」。同じ版の割り込み通知は繰り返さず、設定から常時確認可能 |
| 新版あり・自動更新オン | バックグラウンドでダウンロード・署名検証。「更新の準備ができました」を表示し、安全な終了時に適用、またはユーザーが「更新して再起動」を選択 |
| 重要なセキュリティ更新 | 自動更新のオン・オフにかかわらず理由と修正版を目立つ形で表示。通常更新の「後で」による非表示を適用しない。保存して更新する導線を提供 |

「終了時に適用」は全ウィンドウの未保存編集、保存中処理、発表・外部処理との
連携を確認してから実装する。安全な終了を保証できなければ準備完了で止め、
明示的な「更新して再起動」で適用する。保存失敗・保存のキャンセル時は進めない。

### 設定と通知

- 「更新を自動確認」と「更新を自動ダウンロードして終了時に適用」を区別する。
  後者がオンなら自動確認も有効にする。初期値案は自動確認オン・自動更新オフ。
- 自動確認をオフにした場合、セキュリティ更新も新たに検出できないことを設定説明に含める。
- 通常の新版通知はアプリ内で行う。OS 通知の権限は初期実装では要求しない。
- ダウンロード進捗、準備完了、適用失敗を区別し、失敗後は再試行できる。
  オフラインを「最新版」と表示しない。自動確認失敗で編集を妨げない。
- 自動確認は最終試行時刻で頻度を制限し、失敗時は間隔を空けて再試行する。
  手動確認と自動確認が重なった場合は同じ処理の結果を共有する。

### セキュリティ更新

- 「新版がある」と「このバージョンにセキュリティ上の問題がある」を別に判定する。
  最新版のフラグだけでは中間の修正版まで警告するため、対象バージョン範囲、
  修正版、理由、告知へのリンクを配布側が指定できる形にする。
- 対象バージョンには自動更新がオフでも強く更新を促す。
  更新までの利用制限、強制終了、作業中の無断再起動は行わない。
  通知が出ても編集・保存・書き出し・終了を継続できる。
- セキュリティ告知自体の改ざん対策が必要。
  Tauri の成果物署名が独自ポリシーも保護するとは扱わず、署名付きポリシーの
  検証方法、期限・古いポリシーへの巻き戻し対策を設計する。
- オフラインや自動確認オフの端末では、新しいセキュリティ告知を検出できない。
  更新確認できない場合も、オフラインでの利用を継続できる。

### 配布と障害時

- 安定版と prerelease を区別し、安定版ユーザーへ RC を自動配布しない。
  現在の `0.1.0-rc.6` から安定版への遷移も検証する。
- バージョンは SemVer で比較。対応 OS・CPU の成果物がない場合は適用しない。
- 全成果物の署名・公証・アップロードを確認してから更新 manifest を公開する。
  初回は GitHub Release の静的 manifest を候補とし、ポリシー配布方式は要調査。
- 更新署名鍵は CI Secret と安全なバックアップで管理する。公開鍵の切り替え手順も残す。
- 通信・署名検証・適用の失敗を区別する。壊れたダウンロードを適用しない。
  自動ダウングレードは行わず、不具合版は配布停止と修正版で対応する。
  手動インストールへのリンクも残す。

## レイヤー配置案

- Rust の更新専用モジュール: アプリ全体で一つの確認・ダウンロード・適用処理、
  スケジュール、署名検証、終了時の調整。`lib.rs` は配線のみ。
- domain: バージョン・セキュリティ対象範囲・通知や適用の可否を判定する純粋関数。
- state / ipc: 更新状態と操作、全ウィンドウへの状態共有。
- components: 設定、更新案内、進捗、保存して更新する画面。日本語・英語に対応。

## 受け入れ条件・テスト

- [x] 手動確認で、最新版・新版あり・通信失敗の各結果が表示される
- [ ] 自動確認の時間境界、復帰、複数ウィンドウ、手動との競合で重複処理しない
- [x] 自動更新オフなら自動ダウンロード・適用しない。設定変更後の進行中処理も定義する
- [x] 同じ通常版の通知を繰り返さず、セキュリティ対象版は通常の非表示設定を上書きする
- [x] セキュリティ通知中・オフライン・更新確認失敗時も編集・保存・書き出しを継続できる
- [ ] SemVer、RC → 安定版、対象範囲の境界、不正 manifest / ポリシーを検証する
- [ ] ダウンロード切断・署名不一致・適用失敗後に作業を継続し、再試行できる
- [ ] 未保存編集・保存失敗・発表中・複数ウィンドウで無断再起動や編集消失が起きない
- [ ] 公証済みアプリで旧版 → 新版を実機検証し、再起動後の版と設定・デッキ保持を確認する
- [x] `bun test` / `bun run typecheck` / Rust の関連テストが通る

## 実装結果と残作業

- 初期値は自動確認オン、自動更新オフ。更新設定は既存の保存・全ウィンドウ配信に統合。
- アプリ全体で確認・ダウンロードを排他実行。最終試行・通常通知の非表示版・
  署名付き manifest を保存し、既知のセキュリティ告知をオフラインでも表示する。
- manifest 自体の署名と更新アーカイブの署名を検証し、updater が使う manifest と照合する。
- 終了時に全ウィンドウへ保存要求を送り、失敗・タイムアウトなら終了を取り消す。
  適用はバックグラウンドで行い、管理者認証のためイベントループを維持する。
  適用中の再度の終了・ウィンドウ閉じ・新しいデッキを開く操作を抑止する。
- `meta/update-security.json` をリリース manifest に組み込み、安定版だけに公開する CI を追加。
- 自動検証: TypeScript 型チェック、フロント全テスト、Rust 全テスト、更新・設定のブラウザテスト。

配布前に必要:
- [ ] GitHub Variable `TAURI_UPDATER_PUBLIC_KEY` と Secret `TAURI_SIGNING_PRIVATE_KEY`（必要ならパスワード）を設定
- [ ] CI で署名・公証済み updater アーカイブと manifest の生成・公開を実行確認
- [ ] 実機で旧版 → 新版の適用、管理者認証、複数ウィンドウ保存、次回起動の版と設定・デッキ保持を確認
