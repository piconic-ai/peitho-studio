# レイアウト画面の再設計: ファイル | エディタ | レイアウト一覧

進捗管理用の作業台帳 — **完了したら削除ないし`todo/archive/`へ移動する**。

発端: ユーザーとの相談(2026-10-05)。HTMLモック
(https://claude.ai/artifact/HApLhaYFqAwQjszxr3wFft の「提案B」)で方向性を確認した。
- 左にVS CodeのExplorerのようなファイルツリーを置き、`base.css`など共有ファイルも
  Studioの中で編集できるようにする。
- 中央はエディタ。開いたファイルをタブで並べる。
- 右はレイアウト一覧。プレビューを兼ねる(選択中のレイアウトを上に大きく、
  他は2列の小さなサムネイル)。`base.css`を編集すると全サムネイルに効き、
  影響範囲が一目で分かる。
- スライド画面とは「左=選ぶ場所、右=見た目の結果」の規則で揃える。
追加の要望: 一覧にレイアウトの英名(ファイル名)も表示する。エディタでも
コメントしてAI Agentに依頼できるようにする。
「JavaScriptのタブ」は今回は扱わない(ユーザー指示)。

前提: `todo/layout-screen-rearrange.md`(#163: エディタ|一覧、選択行のライブ描画、
サムネイルのクリックでコメント)、`todo/archive/layout-editor-sync.md`(#164: 自動保存、
外部変更の反映)、`todo/viewport-device-presets.md`(#165: 端末プリセット・実寸表示)、
`todo/layout-review-comments.md`(#162: crit経由のレイアウトコメント)。

## スコープ

- **目的**: レイアウト画面を、ファイル単位で自由に編集できる作業場にしつつ、
  レイアウト単位の操作(適用・複製・削除・コメント)と見た目の確認を右の一覧に
  集める。
- **やらないこと**:
  - JavaScriptのタブ、`layouts/<name>.js`のような別ファイルの規約。
  - ファイルツリーでの作成・リネーム・削除・移動(最初は「開く・編集する」だけ。
    レイアウトの作成・複製・削除は従来どおり一覧の右クリックで行う)。
  - 画像・フォントなどバイナリファイルの編集(ツリーには出すが、開いても
    編集できない。プレビュー表示もしない — 先送り)。
  - `deck.md`の編集(スライド画面で行う。ツリーには出さない)。
  - スライド画面のエディタ(本文・ノート)への行コメント。
  - issue #161(下書きフォントの分離)。
- **受け入れ条件**:
  - レイアウト画面が左から「ファイルツリー | エディタ | レイアウト一覧 | コメント列」
    の順に並ぶ。境界はドラッグで幅を変えられる。
  - **ファイルツリー**: `layouts/`・`css/`・`img/`・`fonts/`を表示し、フォルダを
    開閉できる。テキストファイル(`.html`/`.css`)を選ぶとエディタのタブで開く。
  - **エディタ**: 開いたファイルをタブで並べ、切り替え・閉じることができる。
    どのファイルも自動保存され(#164と同じ間隔と保存前検査)、外部での変更が
    反映される(#164の衝突のお知らせも同じ)。`css/base.css`など、どのレイアウトの
    組にも属さないファイルも編集・保存できる。
  - **レイアウト一覧**:
    - 選択中のレイアウトは上に大きく表示し、編集中の内容をライブで描く(#163の
      下書き描画を移す)。他のレイアウトは下に2列の小さなサムネイル。
    - 各レイアウトに表示名と**英名(ファイル名、例: `title-body`)**の両方を出す。
    - 右クリックのメニュー: スライドに適用 / 複製 / このレイアウトにコメント… /
      削除…(空白の右クリック: 新規レイアウト / レイアウト全体にコメント…)。
      「レイアウトを編集」は無い。
    - PC/スマホ切替は一覧の左上(#165の端末プリセット・実寸表示はそのまま)。
    - 大きく表示した選択中のレイアウトをクリックすると、AIへのコメント欄が開く
      (#163のslot判定つき)。
  - **選択の連動**:
    - 一覧でレイアウトを選ぶと、その`.html`と`.css`がエディタのタブで開き、
      ツリーでも強調される。
    - ツリーでレイアウトの`.html`/`.css`を開くと、一覧でもそのレイアウトが選ばれる。
    - どのレイアウトにも属さないファイル(`base.css`など)を開いた時は、一覧の
      選択はそのまま(最後に選んだレイアウトを大きく表示し続ける)。
  - **エディタからのコメント**: エディタで行を選んで(またはカーソル行で)コメント
    すると、そのファイルのその行範囲へのコメントとしてcrit経由でエージェントに
    届く。ラベルは`[layouts/title-body.html L3-L5 "…引用…"]`のようにファイル名・
    行・引用を含む。スライド画面と同じコメント欄(`CommentBox`)と送信の流れを使う。

## 背景・要調査

読んで分かったこと:

- 今の配置(#163): エディタ | 一覧(選択行の下書きライブ描画、サムネイルクリックで
  コメント) | コメント列。エディタはHTML/CSSの2タブで、1つのレイアウトの組
  (`layouts/<name>.html` + `css/<name>.css`)しか開けない。`base.css`は触れない。
- 保存は`save_layout`(レイアウトの組単位、保存前にビルド検査)。自動保存・外部変更の
  反映は#164(`layout_files_stamp`、`layouts/`・`css/`の監視、衝突のお知らせ)。
- レイアウトへのコメントは`NewLayoutComment { layout: string | null, body, author }`
  (`domain/critReview.ts`、`src-tauri/src/engine/crit.rs`の`layout_comment_place`)で、
  行の情報を持たない(ファイル全体、またはreview-level)。一方、`deck.md`への
  コメントは`start_line`/`end_line`/`quote`つきで送っている(`POST /api/file/comments`)。
  critのセッションは`deck.md layouts css`を対象にしているので、レイアウトの
  ファイルへの行コメントは同じAPIで送れるはず(要確認)。
- エディタは`dom/codeEditor.ts`(CodeMirror)。Vim mode、折り返しなし、Undoの扱いは
  #157/#163のまま。

要調査(実装の最初に確かめ、結果をここに書く):
1. critの`POST /api/file/comments?path=layouts/<name>.html`に`start_line`/`end_line`/
   `quote`を付けて送れるか(同梱critで実際に試す)。
2. `base.css`のようにレイアウトの組に属さないファイルを保存する時の検査:
   変更後に今ビルドできている全スライドがビルドできるかを検査する(`save_layout`の
   検査を一般化した`save_deck_text_file`のような形)。対象パスは`layouts/`・`css/`
   配下の`.html`/`.css`に限り、パスの検証(`..`やシンボリックリンク)を入れる。
3. ファイル一覧の取得: `layouts/`・`css/`・`img/`・`fonts/`を列挙するRustコマンド
   (サブディレクトリの扱い、隠しファイルの除外)。
4. CodeMirrorで選択範囲(行)を取得し、コメントの開始UIをどこに置くか:
   推奨は「選択中に出る小さな『コメント』ボタン」+エディタの右クリックメニュー。
   Vim modeのビジュアル選択でも使えること。

## 方針

- 段階を分ける(1つのPRでよいがコミットを分ける):
  1. 配置の組み替え(ファイルツリー、タブ付きエディタ、右の一覧に選択中の大表示)
  2. 任意ファイル(`base.css`など)の保存・自動保存・外部変更の反映
  3. 選択の連動
  4. 一覧への英名表示
  5. エディタからの行コメント
- 右の一覧は#163のライブ描画・#165の実寸表示を引き継ぐ。選択中のレイアウトの
  大きな表示がプレビューの役割を担う。
- エディタのタブの状態(開いているファイル、どれが前面か)は`state/`にADTで持つ。
  未保存・衝突の扱いはタブごと(#164の`LayoutEditor`をファイル単位に一般化)。

## レイヤー配置

- Rust `engine/`: ファイル一覧の列挙、対象パスの検証、任意ファイル保存の検査、
  行つきレイアウトコメントの組み立て(純粋関数)。
- Rust `peitho.rs`: コマンド(`list_deck_files`、`read_deck_file`、`save_deck_file`など)。
- フロント `domain/`: ツリーの組み立て、タブのADT、ファイル→レイアウトの対応
  (`layouts/x.html`/`css/x.css`→`x`)、行コメントのターゲットとラベル。
- `state/`: タブ、ツリーの開閉。`components/`: `FileTree.tsx`、エディタのタブ、
  `LayoutScreen.tsx`の組み替え。配線は`Studio.tsx`。

## テスト

- Rust spec/adversarial: ファイル列挙(空ディレクトリ、隠しファイル、
  サブディレクトリ)、パス検証(`../`、絶対パス、シンボリックリンク、対象外の拡張子)、
  任意ファイル保存の検査(`base.css`の変更でビルドが壊れる→拒否)、行つきコメントの
  組み立て。
- TS spec/adversarial: ツリーの組み立て、ファイル→レイアウトの対応、タブのADT
  (同じファイルを2度開く、開いているファイルが外部で消える)、行コメントのラベル
  (1行・複数行・空行・長い引用)。
- e2e(mockTauri): 配置の順序、ツリーでファイルを開くとタブが増える、一覧で選ぶと
  タブとツリーが連動する、`base.css`の編集が全サムネイルに効く、英名の表示、
  エディタで行を選んでコメントするとcritに行つきで送られる。
