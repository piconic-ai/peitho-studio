# 同一ディレクトリの多言語デッキ切り替え

進捗管理用の作業台帳 — **完了したら削除ないし`todo/archive/`へ移動する**。

発端はユーザー要望: 同じディレクトリに`deck.md`以外に`deck.ja.md`の
ような他言語版デッキがあったら、簡単に切り替えできるようにしたい。
壁打ちの結果、検出基準は「同じbase名 + 任意のサフィックス」
(`deck.md`に対し`deck.<任意の文字列>.md`を全て候補とし、サフィックス
文字列をそのままラベル表示する — ja/en等のISO言語コードに限定しない)
に決定。

## スコープ

- **目的**: 同一ディレクトリにある同base名の`*.md`デッキ間を、Studio上
  で簡単に切り替えられるようにする。
- **やらないこと**: 翻訳の自動生成・同期機能、スライド単位の対訳
  マッピング(どのスライドとどのスライドが対応するかの管理)。
- **受け入れ条件**: 同base名の候補が2件以上あるデッキを開くと切り替え
  UIが表示され、選択すると該当ファイルが開く。候補が自分自身のみの
  場合はUIが表示されない。

## 背景

- 現状、同一ディレクトリの兄弟ファイルを列挙するIPCコマンドは存在しない
  (`ipc/deckIpc.ts`の`DeckIpc`インターフェース、
  `src-tauri/src/peitho.rs`のコマンド一覧いずれにもなし)。
- `DeckSessionInfo`(`open_deck`の戻り値)は`deckPath`/`deckDir`/
  `render`を持つので、`deckDir`を起点に兄弟ファイルを探索する形になる。

## 方針

### 検出ロジック(純粋関数、Rust側 or フロント側どちらに置くか要検討)

- 開いているファイル名から`<base>.md`または`<base>.<suffix>.md`の
  どちらの形かを判定し、同じ`<base>`を共有する`*.md`をディレクトリ内
  から拾う。
  - 例: `deck.md`を開いている → `deck.ja.md`/`deck.en.md`等を候補に。
  - 例: `deck.ja.md`を開いている → `deck.md`(無印)と`deck.en.md`等、
    同じ`deck`baseを共有する他ファイルを候補に。
- ディレクトリ列挙自体はファイルI/Oなので新規Tauriコマンド
  (`list_deck_variants`のような名前)をRust側に追加し、
  「同base名でグルーピングする」判定ロジック自体は`(Path, &str) ->
  Result<T, String>`の形の純粋関数として`src-tauri/src/engine/`配下
  (または新規モジュール)に切り出す — ファイルシステム走査という副作用と
  グルーピング判定という純粋ロジックを分離する。

### UI

- `DeckHeader.tsx`の現在のデッキパス表示の隣に、候補が2件以上あるときだけ
  切り替えドロップダウンを出す(候補が1件=自分自身のみなら何も出さない)。
- 切り替えは既存の`open_deck`系の経路(別ウィンドウで開く/同ウィンドウで
  差し替える、いずれにするかは`open_deck_window`の既存挙動に揃える)を
  再利用する。

## 未解決の論点

- 切り替え時、同じスライド位置(選択中のスライドindex)を新しいデッキ側に
  引き継ぐか、それとも単純に先頭スライドから開き直すか。中身が違う
  デッキ(翻訳漏れ等でスライド枚数がずれる)もあり得るため、
  「indexが範囲内なら維持、外れたら先頭」程度の単純なフォールバックが
  無難か — 実装時にFableと確認する。
- 同base名ファイルが1件も見つからない(単独デッキ)場合はUI自体を
  出さない、という理解でよいか要確認。

## テスト

- グルーピング判定の純粋関数について spec(`deck.md`+`deck.ja.md`+
  `deck.en.md`が同グループになる、無関係な`deck-old.md`は含まれない)
  + adversarial(base名が空、拡張子違い`.markdown`、大文字小文字混在、
  隠しファイル`.deck.md`)。
